# Отчёт о проделанной работе

- Время: 2026-10-22 16:35:51
- Задача: устранение ошибки `0xc000001d` при загрузке локальной LLM

## Проблема

При запуске `src/rag_pipeline.py` возникала ошибка `OSError: [WinError -1073741795] Windows Error 0xc000001d` (illegal instruction) при загрузке модели. Установленный wheel `llama-cpp-python 0.3.16` был собран с инструкциями AVX2/AVX-512, которые не поддерживаются процессором.

Процессор: AMD Ryzen 5 5500U (Zen 2) — поддерживает AVX2, но не AVX-512.

## Выполненная работа

1. Удалён `llama-cpp-python 0.3.16`.

2. Ссылка из инструкции (`Srinadhch07/llama-cpp-python-wheels` релиз `v0.3.21`) вернула HTTP 404: в этом репозитории есть только релиз `v0.3.16` (AVX-вариант), релиза `v0.3.21` не существует.

3. Вместо неё установлен официальный wheel с базовой поддержкой CPU (без AVX):
   - `llama-cpp-python 0.3.36` (`llama_cpp_python-0.3.36-py3-none-win_amd64.whl`) из релизов `abetlen/llama-cpp-python`.

4. `requirements.txt` обновлён: строка `llama-cpp-python @ ...` теперь указывает на wheel `abetlen/llama-cpp-python v0.3.36 py3-none-win_amd64` (базовая CPU-сборка), комментарий поясняет причину.

## Проверка

- Прямая загрузка модели прошла успешно:
  ```
  MODEL LOADED OK in 1.3 s
  GENERATION OK: ' всем! Я новичок в программ'
  ```
- `src/rag_pipeline.py` стартует без ошибки `0xc000001d`: загружает эмбеддинги, LLM (CPU), индекс ChromaDB (19 чанков) и доходит до приглашения «Введите вопрос».

## Итог

Ошибка `0xc000001d` устранена заменой wheel на базовую CPU-сборку без AVX. Модель Qwen2.5-1.5B загружается и генерирует текст.
